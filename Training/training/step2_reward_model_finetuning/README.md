# Reward Model (RM) finetuning

Fine-tuning the Reward Model (RM) is similar to Step-1 Supervised Fine-Tuning (SFT), but with several key differences that are important for understanding how RM fine-tuning works in the context of our research.

**The training data difference**

In SFT fine-tuning, the data consists of a single query-answer pair. However, for RM fine-tuning, each training batch consists of two query-answer pairs: one with a high-score answer and another with a low-score answer. This pairwise structure is crucial for training the reward model effectively.

**The training objective difference**

The training objective for the RM is to assign a pairwise ranking score. In other words, for two query-answer pairs, the RM is expected to assign a higher score to the better answer. In our implementation, we use either the end token of the sequence or the first padding token as the aggregated score, comparing the two. Other alternatives may include using the average score across the entire answer.

**The `--num_padding_at_beginning` argument**

An interesting aspect of the RM fine-tuning script is the argument `--num_padding_at_beginning`. We included this argument because we noticed that different models exhibit varying padding and tokenizer behaviors. For instance, the OPT model family’s tokenizer always adds a padding token at the beginning, which can influence how we select the scoring tokens. This consideration led us to add this argument to ensure correct handling of padding during fine-tuning.

**The RW evaluation**

We also provide an evaluation script, `rw_eval.py`, to facilitate simple prompt-answer testing. Below is an example using the 350M RM model to demonstrate how to evaluate the model after fine-tuning.

## How to train the model

We have provided the training script for the OPT-350M model, which can be easily tested by running:

```
bash training_scripts/single_gpu/run_350m.sh
```

For larger models, you can simply replace the model candidate with your preferred model and enable other efficient training features, as detailed in Step 1 of the SFT fine-tuning process.

## Other Considerations

During training with different datasets, we occasionally observed negative average reward scores at the end of training. Despite this, feeding such a Reward Model (RW) into Step 3 (RLHF fine-tuning) still allowed the actor model to improve and learn higher reward scores. Additionally, the hyperparameters provided in our script have not been extensively tuned. Therefore, we encourage users and practitioners to experiment with different hyperparameter settings to optimize their models for better performance.
